# Changelog: comfyui-magik-timeline node pack

Changes to the nodes themselves. The workflows have their own changelog: [workflows/README.md](workflows/README.md).

Changes not yet in a release are listed under **Latest HEAD**; they become a numbered version when the pack is released.

## Latest HEAD

- Changed: **dual-resolution is now two nodes, because the one-node form had a dependency cycle.** `target_latent_hr` was an input of the node that also produced stage 1's `latent`; when the stage-2 latent comes from stage 1's own sampler (upscaled), ComfyUI cannot order the graph. Removed from **H3 MCtx Apply Pins**: `target_latent_hr`, `lr_encode_source` (Path B never ran), and the outputs `conditioning_hr` / `latent_hr` (the node has its three outputs again). Added: the `two_stage` switch (stage 1 only: pixel-grade pin at this latent's resolution, exact full-resolution slices left on `pins`, sized from the pinned clip; a source with no sidecar is refused) and the new node **H3 MCtx Apply Pins Stage 2** (`MAGIK_H3MCtxApplyPinsStage2`, the 20th class): `pins` + the upscaled, sampled latent in; stage-2 conditioning, masked latent and the pins out. Flow: Apply Pins (`two_stage`) → sampler 1 → latent upscale → Apply Pins Stage 2 → sampler 2 → Trim/Save. Stage 2 refuses a resolution that is not the pinned clip's, a length that differs from stage 1's (pins carry `stage_frames`), an unwired latent output and non-pins input; an inherited stage-1 mask is stripped. Workflows saved against 0.3.x/0.4.0 with `target_latent_hr` connected need rewiring. Tests: `tests/test_dual_resolution.py` adapted (stage 1 then stage 2), `tests/test_dual_split.py` added (not yet run).

## 0.4.0 (2026-11-03)

- New: **`migrate_workflows.py`** — the one-time workflow migration the 0.2.0 release promised ("a remap script ships with the Phase 5 release"). A workflow JSON saved against upstream 0.1.4 stores the old class names in `nodes[].type` and inside group-node / subgraph definitions; the script remaps any `type` / `class_type` value that is exactly one of the 19 names in [docs/MAGIK_PORT.md](docs/MAGIK_PORT.md) §1.1 (`H3Timeline` → `MAGIK_H3Timeline`; `class_type` covers the API/prompt format, and the recursive walk reaches group-node definitions whatever key they ride under). Stdlib only — it runs on a machine without ComfyUI. Stricter than the substring replace the port doc originally suggested: a note whose prose mentions `H3Timeline`, or a group titled `H3 Joint Refine Sampling`, survives untouched, because only exact `type` / `class_type` values are considered class names (links, widget values, wire types `OBVPM_H3_*` / `OBVPM_BUNDLE`, companion nodes like `MinimaxH3LatentUpscaler3D` are never touched). Idempotent: an already-Magik workflow comes out `clean` and byte-identical, no `.bak` clutter. In-place mode backs up each file it changes as `.bak` (`--no-backup` skips); `--out DIR` writes remapped copies and leaves originals alone; `--reverse` is the exact mirror for rollback; folders are walked top-level-only (no recursion surprises); an unparseable file is reported and skipped, the others still migrate, exit status 1. Verified end-to-end against a shipped `workflows/*.json` with its prefixes stripped: the migration's output type list is identical to the shipped file's (848 type strings, nested definitions included).
- New test module `tests/test_migration.py` (15 tests): the walk remaps every upstream type in a synthetic workflow carrying all the real shapes (plain nodes, API format, nested group-node definitions, links, widget values, prose mentions, group titles, companion nodes, the `Node name for S&R` property); nothing but the type values moves; the hardcoded 19-name list is pinned to the pack's own `NODE_CLASS_MAPPINGS` so script and node pack cannot drift apart; idempotency; the reverse mapping is the exact mirror; the CLI end-to-end (in place + `.bak`, already-Magik byte-identical, `--out`, `--reverse`, folder walking, unreadable-file exit status).
- Full regression suite finalized: **313 unittest tests → OK** (1 pre-existing skip) + 5/5 frontend `.mjs` scripts. Breakdown: 257 upstream-porting + 28 dual-resolution + 12 pixel-grade-seam + 13 Phase 4 acceptance + 15 migration. The full-suite record and the exact commands (`python tests/run_all.py`; `node tests/*.mjs`, needs `npm install` once) are in [docs/MAGIK_PORT.md](docs/MAGIK_PORT.md) §4.
- Roadmap closed: port (0.2.0) → dual-resolution (0.3.0) → acceptance harness (0.3.1) → migration script + finalized suite (0.4.0). What remains outside the code is the Phase 4 real-data run itself, which needs a ComfyUI + MiniMax H3 machine: the runbook is [docs/MAGIK_PHASE4_ACCEPTANCE.md](docs/MAGIK_PHASE4_ACCEPTANCE.md).

## 0.3.1 (2026-11-03)

- New: **Phase 4 acceptance experiment harness** -- the runnable form of the audit's ch. 11.7 boundary condition. The experiment decides whether the Path C pixel-grade LR pin (the 0.3.0 default) clears the seam-quality bar, or whether Path B (decode -- resize -- re-encode) needs to be built as a new ``latent-resample`` grade level. The design rationale is `Magik_Timeline_Upstream_Audit.pdf` ch. 11.7; the operator runbook is [docs/MAGIK_PHASE4_ACCEPTANCE.md](docs/MAGIK_PHASE4_ACCEPTANCE.md).
- Three new top-level modules, no new node class, no new wire type, no new route:
  - `phase4_protocol.py` -- the protocol as code: the three arms (control, test_path_c, ref_path_a), what is held constant, what is measured, and the `acceptance()` function that applies the audit's two-axis criteria (verdict band not worse than control AND drift measurably reduced). The thresholds are lifted verbatim from `seam_report.py` (`SEAMLESS_BELOW = 1.45`, `SOFT_BUMP_BELOW = 1.9`), so the protocol and the metric share one source of truth.
  - `phase4_synthetic.py` -- a deterministic stand-in for a real ComfyUI run on the same `FRAMES_PER_GROUP = 17` / `LATENTS_PER_GROUP = 5` grid. The seam metric is latent-space, so it can be exercised without a model, a VAE or a GPU; the only thing that has to be honest is the latent grid structure and the phase-structured noise. Generates three arms (control: clean handover + free generation drift; test_path_c: pixel-grade seam shift + pin-anchored generation; ref_hard_cut: hard-cut spike, a sanity check that the metric CAN detect a real failure). Ships a synthetic baseline result at `phase4_result_synthetic_baseline.json`: control ratio 1.005 (seamless, drift 0.080), test_path_c ratio 1.083 (seamless, drift 0.000), ref_hard_cut ratio 1.915 (hard cut). Acceptance: PASS.
  - `phase4_run.py` -- the real-data harness. Loads takes from two folders (`--control`, `--test`), measures each extend/prepend take's seam via `seam_report.measure_seam`, its drift via `phase4_synthetic.composition_drift`, and (when the `.mp4` is present) its frame-difference cut scan via `seam_report.measure_cuts`; aggregates per arm and applies `phase4_protocol.acceptance`. Writes the result JSON to `--out`. The drift metric here is an approximation of the audit's against-source drift (it uses the take's own pinned span as the baseline); the runbook flags takes whose own-span drift reads low but whose fidelity is also low as uninformative.
- New test module `tests/test_phase4.py` (13 tests): arms land in the right verdict band (seamless / seamless / hard cut), acceptance logic matches the audit's two axes (verdict-band regression caught, drift regression caught), ordering is physical (clean < pixel < hard cut on the seam; test < control on drift), and the synthetic baseline is deterministic across runs. Full suite: 298 tests OK (1 pre-existing skip).
- New doc [docs/MAGIK_PHASE4_ACCEPTANCE.md](docs/MAGIK_PHASE4_ACCEPTANCE.md): the operator runbook -- the protocol (arms, held-constant, measured), how to run the synthetic baseline and the real-data harness, the result template, and the fallback policy if Path C fails (build Path B as a ``latent-resample`` grade behind an explicit experimental flag; if Path B also fails both axes, revisit the audit's ch. 11.4-11.6 before building anything else).
- The acceptance is a runnable form of an existing condition, not a node change: ``lr_encode_source: latents`` (Path B) stays selectable-but-refuses until the real-data Phase 4 run decides otherwise, exactly as 0.3.0 shipped.

## 0.3.0 (2026-11-03)

- New: **dual-resolution mode on H3 MCtx Apply Pins** — connect the optional `target_latent_hr` input and one pin window feeds two stages. The stage-2 (high-resolution) pin is the exact sidecar slice, through the unchanged latent slicer; the stage-1 (low-resolution) pin is the same window re-encoded from the source file at the stage-1 resolution — pixel grade through the unchanged pixel route (Path C, the audited default). Built for the two-stage flow: first sampler at a lower resolution, spatial latent upscale (temporal length kept), second sampler at the source's native resolution. Implemented per the Phase 1 audit's boundary rules R1–R7 and node contract (Table 12-1); the design rationale is `Magik_Timeline_Upstream_Audit.pdf` ch. 11–12.
- One shared temporal record: the window is resolved once against the stage-2 target; the stage-1 encode is driven by the resolved record (its window length, snapping off) and verified to cover the same file interval of the same file — the two stages cannot pin different moments, and nothing re-snaps independently (R3).
- The audio slice is computed once by the exact route and shared by both stages; audio timing is metadata on the record, never a per-stage recomputation (R4) — audio has no spatial axes, so one slice serves any resolution.
- Conditioning and masks are per stage and never mixed (R5): new outputs `conditioning_hr` / `latent_hr` carry the stage-2 pair, and a stage-2 target that arrives carrying stage 1's noise mask (it rides through the latent upscaler) has it stripped — loudly — before the fresh HR mask is written, instead of refusing the compose the way a single-resolution run must.
- The `pins` wire carries the stage-2 (authoritative) records with `stage_resolutions` / `stage_grades` attached as run-time fields; `serialize_pins` copies named fields only, so the sidecar recipe is untouched — a dual take still saves with `source_kind: clip`, lineage grade `latent`, exactly as a single-resolution one (R7). Standard mode (input unconnected) behaves exactly as 0.2.0 did and returns `None` on the two new outputs; saved workflow links are unaffected because the new outputs are appended after `pins`.
- Refusals stay loud in dual mode (R6): a stage-2 resolution mismatch names both sizes; missing VAEs name what Path C needs; a source file whose hash no longer matches the sidecar that verified the HR slice is refused (the two stages would pin different content); through-pins (`via`) and `lr_encode_source: latents` (Path B) are refused until the Timeline's dual integration and the Phase 4 acceptance experiment arrive.
- New test module `tests/test_dual_resolution.py` (28 tests): one record / two representations, same interval, per-stage grades, shared audio, mask strip, wiring checks at both latent outputs, standard-mode byte-compatibility, recipe immunity.

## 0.1.4 (2026-10-08)

- New: **H3 Live Preview**, the sampler's picture while it samples, in the Result Preview: each step as a short clip on the take's own timeline (every latent step held for the frames it covers, so no frame rate to set), the pinned frames at the ends included so a join can be judged while it is made, encoded as H.264 on the CPU without holding up sampling. Put it on the model the sampler uses; it decodes with a tiny VAE for H3 from `models/vae_approx` (`taeh3.safetensors`), or the latent's own colours without one. It replaces KJNodes' Model Preview Override, which the Result Preview still shows when that is what is in the graph. See [H3 Live Preview](docs/h3-nodes.md#h3-live-preview).
- New: the Result Preview plays with a bar of its own **below** the picture -- play / pause, frame step, seek, time, a volume slider, loop, fullscreen -- instead of the browser's controls drawn over the bottom of the frame. Click the picture to play or pause, double click for fullscreen (where the bar lies over the picture and slides away while the mouse rests), scroll sideways over the picture or the bar to step along it, and **Space** plays or pauses the preview under the mouse (or the selected one; the lone Timeline keeps Space otherwise). The live picture plays under the same bar: it no longer starts over at every sampling step, so the whole clip can be watched, paused, seeked and looped while the Run samples. A take a Run just made starts playing by itself; one shown again when the workflow opens is shown paused at its start. Sound, volume and loop are remembered in this browser.
- Fixed: takes in a folder that is a **symlink or Windows junction** inside the output folder (a project folder kept on another drive, say) could be saved and were listed, but loading, extending, upscaling or previewing them failed with "... escapes the output folder": clip paths were checked after resolving links, while saving checked them as written. They are now checked as written everywhere, as core ComfyUI does -- `..`, absolute and drive paths still cannot leave the output folder, but a link inside it is followed wherever it points. The clip lists walk linked folders too (a symlinked folder was skipped), each real folder once, so a link pointing back up the tree neither loops nor lists the same takes twice, and a link never takes a real folder's place in the list.
- Fixed: **+ add to timeline** moved the clip a prepend leads into, and everything after it. A prepend hands over inside that clip (at its frame 13 with the default soft hold, later after a cut), which cuts the clip's start; the empty space before it gave up only the take's own length, so the clip slid earlier by the frames cut off (0.54 s at frame 13) and the space came out that much shorter. The space now also takes back those frames, so the clip and everything after it stay where they were. The same for an extend that leaves its clip a little before its end (the last latent step): what follows the space after it keeps its place. Bridges, and a prepend into a clip with no space before it, are placed as before.
- Fixed: an 8.3 ms skip in the sound at extend joins. A pin window that starts between two audio steps -- from a clip whose length is not a multiple of 3, like 124 or 362 frames, or such a cut -- is sliced from the nearest step, so the take's sound sits a third of a step off its own frames. The latents keep that (the upscale lays every clip on one audio grid and joins them exactly), but the take's MP4 now has its sound cut on its own frames, and so does the crossfade overlap; the sidecar records `audio_phase` and `audio_synced`. So a take plays in sync on its own, and its join in previews and exports no longer skips 8.3 ms (measured: 267 samples to 0). Takes saved before are corrected the same way when a preview or export is built. The held sound is now sliced from the step nearest the window's first frame in true time (the source's own phase included), so a take is never more than half a step off and nothing adds up along a chain. Previews rebuild once.
- Fixed: in the upscale, a take extended from an off-grid cut of a take that was itself off-grid could skip or repeat a whole audio step (25 ms) at its junction: each clip's sound was placed by rounding its own start. It is now placed by lineage -- its parent's first step plus the step its held sound came from -- so every junction continues the parent's sound exactly; takes saved before are placed by the same rule they were sliced with.
- Fixed: on extend joins that crossfade (guide or both mode pins, or crossfade turned on for a masked join), the last few milliseconds before the join were near-silent in the timeline preview and export and in the Result Preview's joined preview -- 3 to 30 ms depending on the overlap (7 ms for 39 frames, 26 ms for 90) -- and the take's sound in the fade ran that much early. The take's stored overlap is AAC, which decodes padded to whole 1024-sample blocks; the fade read the overlap from its end, padding first. Previews rebuild once. Masked joins without crossfade, the default, were not affected.
- Fixed: continuing a clip from its end logged "unexpected audio grid (603 steps for 362 frames); assuming no overhang" for one clip length in three (56, 107, 158, ... 362 frames). ComfyUI sizes a clip's audio to the nearest 40 Hz step, so on those lengths it ends a third of a step (8.3 ms) before the last frame; the check only expected it to end after. Nothing was wrong with the clips or the takes made from them.
- Changed: a Run whose latent upscaler (MinimaxH3LatentUpscaler3D) has `enable_temporal_chunking` off is refused, saying which node and how to fix it. Upscaling without temporal chunking was seen inventing details the clip never had (hallucinations), which the refine then keeps, and nothing is gained by turning it off. The upscale is stopped at H3 Joint Audio Mask, before the refine samples anything. It walks back up its own inputs in the queued prompt, so only an upscaler that actually feeds it counts, and a muted one does not.
- **Changed: the Result Preview's live picture has no switch any more.** The right-click **Live preview while sampling** is gone, and the picture always shows while a Run samples (to go without it, take H3 Live Preview, or KJNodes' Model Preview Override, off the model). The switch was kept in the browser per save folder, and older workflows carried `h3_live_preview: false` on the preview they showed the upscale in: opening one turned the live picture off for the take preview of every workflow saving to that folder, with nothing on screen to say so. A preview now shows only the frames of its own branch's sampler, so the one on the upscale branch no longer shows the generation's frames. The stored switch is no longer read (and goes at the browser storage's next write), and the old property is ignored.
- Fixed: a double click or a drag across a node could paint the browser's blue text selection over a whole video. Videos are never text-selected now -- on the Clip Loader, the Timeline and the Result Preview, and any other video on the page (ComfyUI's own previews included). Status lines stay selectable, to copy: the Result Preview's, the Timeline's **next run** line, its selected clip's line and its build progress.
- H3 MCtx Result Preview: the `path` input is now optional, so a preview whose Save node is muted for a Run (a Mute Group If on the `upscaling` output, comfyui-obvpm 0.2.11 or newer) keeps what it shows instead of failing the Run. The *Switching branches* notes in [docs/h3-nodes.md](docs/h3-nodes.md#h3-mctx-timeline) now mute whole groups that way rather than only gating the samplers, so the other half's loaders never start.
- New: **a very short take can be continued.** A pin's window is now taken from the source's whole stored latent: a take made by extending another clip keeps the frames it held from that clip ahead of its own (35 + 33 = 68 raw frames for a 33-frame take), so a 39-frame window ending at its end -- or at a cut close to its start -- reaches back into them, where before the take was "too short to extend". A prepend's window likewise runs on into the frames a prepend-made take led into. Those frames are the take's own latents, identical to the clip it continues there (measured: no difference at all), so the join does not move: the new take still starts at the cut, and the lineage, the seams and the upscale read it as before. A pin from a take's pixels reads its file, which holds only the delivered frames: there the frames before them are read from the file of the clip it continues, and a prepend's frames after them from the file of the clip it leads into (each found as the Result Preview finds it; refused, saying so, when that file is gone). A root clip shorter than the window is refused as before.
- New: **a prepend close to a clip's end.** A prepend's window starts at the cut and runs 39 frames on, so from a cut near the clip's end it ran past it ("cut frame 141 is outside clip_00059.mp4 (1..124 frames)"). When the next line on the timeline is a take that extends this clip, the window is now taken from that take: it stores this clip's frames up to their join, the very same latents (measured: no difference), then its own -- exactly what plays after the cut. The new take is still recorded as leading into this clip at the cut, so the timeline, the seams and the upscale place it as any prepend; its window just runs on past the clip's end. Without such a take the Timeline now says how many frames are left ("a prepend at frame 102 of clip_00059.mp4 needs 39 frames from there, but only 22 are left before the clip ends") instead of naming the window's end as the cut.
- Extends, prepends and bridges: a new take now takes over one latent step earlier at its join -- 4 frames before the end of the clip it extends, or 5 frames into the clip it arrives at with a hard hold (mask ramp 0; the default soft hold already hands over later). The video decoder draws the last frames of a file with nothing after them, and the first frames with nothing before them, so the older clip's frames there never quite matched the new take, which decoded the very same latents in the middle of its own file. That was part of the fine-detail change visible at a join: measured on a 1376x768 extend, the join's detail change drops by about a third, and the rest is the model redrawing the texture, which only the upscale removes. It is just where the two clips are cut, so the quick preview, the full preview, the export and the Result Preview all show it, and nothing is re-encoded. The take records it in its recipe (`handover_edge`), so takes made before keep the join they were cut at. The upscale is unchanged: it renders the same latents either way.
- Timeline: clips joined by a green seam can now be separated. Ctrl+drag the right-hand clip to open empty space between them; both keep playing the frames they played while joined. Dragging it back flush rejoins them.
- Timeline: new **split** button in the middle of the cut row. It splits the clip under the playhead into two clips at that frame (on the snap grid while **snap cuts** is on), which can then be moved, cut or deleted separately. Both halves play the same file; nothing is re-encoded. The button is dimmed while the playhead sits on the clip's edge. The two halves join back-to-back, so an upscale treats the split as a cut.
- Timeline: extend, prepend, bridge and loop now act on the one clip you picked when the same file is in the timeline more than once (the parts of a split clip). Before, all parts showed the pin and it was unclear which one the next run would continue from. The pin row names the part (for example `clip_00033.mp4 (part 2/3)`), the pin carries that part's cut, and the new take is placed next to the part it continues from.
- Timeline: removing a clip with its ✕ now always leaves its time as empty space of the same length (merged with any beside it), so nothing after it moves, and the clips either side keep the frames they played -- before, the rest of the cut slid left to close the hole, and a clip that the removed one had continued could grow back the frames it had been cut at. A clip with nothing after it is simply removed, and so is the first clip of a looping cut. The gap's own ✕ still closes a gap.
- Result Preview: keeps nothing in the workflow any more. A finished run, adding or dismissing a take and its seam settings no longer create undo steps or change the workflow file, an undo elsewhere never brings an older result back, and a shared workflow no longer carries your last result. When a workflow opens, each preview shows this session's result, or else the newest take its Save node wrote (judged as a run would, cached per file). Dismissed takes and seam settings are remembered in this browser; settings saved in older workflows are carried over once.
- Result Preview: **dismiss** now clears the result from the preview instead of only hiding the buttons (the take stays on disk), and is offered for any result on screen, including a take already added to the timeline. A preview you cleared -- by dismissing or deleting its take -- stays empty when the workflow is opened again until a newer take exists. Before, a refresh brought up the take before the one you deleted, which read as a result you did not remember running.
- Result Preview: the upscale preview plays the rendered file itself (`upscale_00001.mp4`) instead of building a preview copy of it, so it starts at once and shows exactly the rendered pixels -- the copy was re-encoded, a second generation of the picture being judged. Only the take preview still builds `magik_h3_result.mp4`. The two used to share that file, rebuilt each other's preview on every look, and two builds at once failed with "The system cannot find the file specified" (`...magik_h3_result.mp4.tmp.mp4`). Builds of one preview file now also run one at a time, each with its own temp file, and an export copies the preview while holding that turn.
- Timeline: the parts of a split clip carry a part id in their sequence line (`[id=k3x9]`; a file that is in the cut only once never gets one), and a pin names its part by that id rather than by position. The pin now stays on its part when other parts are moved, split or deleted; a pin on a clip you split moves to the half that keeps the edge it continues from; and a pin whose own part is deleted is cleared, with the pin row saying so, instead of silently jumping to another part. The new take records its part and the cut it was queued from, so it goes back next to that part even after a reload (or next to the other half, when that part was split meanwhile and the half now owns the edge it continues from), and if that part's cut was changed while the take was generating you are asked whether to put it back (seamless) or keep yours (a cut) -- before, the cut was reset without asking and the message blamed the 17-frame grid.
- Timeline: the seam menu's list of existing takes checks where each take joins, not only which file it continues. Takes of the same file that join at another part's edge, or at a point this part's cut no longer reaches, are listed apart under *joins elsewhere*, dimmed, with their join frame. A green link whose hand cut does not meet the natural join frame now shows as a cut on the strip, matching how the upscale treats it.
- Timeline, fixed: adding a take that leads into a clip whose start is cut -- a prepend, or the right side of a bridge, which is always the case for the right half of a split clip -- left that clip starting where it was cut, so the frames between that cut and where the take hands over played twice: the join looked seamless in the Result Preview and rewound a little in the timeline. The clip now starts where the take hands over, as the clip before a take already ended where the take continues from; if you changed its start while the take was generating, you are asked.
- Timeline: clip and empty-space lengths are shown to two decimals (`2.33s`), like the total below the strip, and so are the space readouts while you drag.
- Timeline: **Space** plays and pauses the preview -- the full build when there is a current one, quick otherwise (Space never starts a build). It goes to the timeline under the mouse, else the selected one, else the only one in the workflow, and acts as the key goes down. Holding Space to pan the canvas still pans (the press toggles playback too), and Space still types in text fields.
- Timeline: after an edit (a cut, a move, a delete, the text editor) the picture shows the new cut at the playhead straight away. Before, it kept showing the old cut until the ruler was touched.
- Timeline: a **sideways wheel** over the ruler or the strip (a mouse's thumb or tilt wheel, such as on a Logitech MX Master, or Shift + wheel) moves the playhead back and forth, by half as far as you scroll, with the picture following; zoomed in, the strip scrolls along with it. A plain up/down wheel is unchanged.
- Timeline, fixed: with Nodes 2.0, the wheel over the ruler and Ctrl + wheel over the strip did not zoom (the node passed the wheel to the canvas first).
- Timeline, fixed: quick play stopped at the first empty space instead of playing through it (a gap has no clip for the info row to describe, and that error ended the playback). The info row now says "empty space" there, and pausing inside empty space holds the playhead where it is.
- Result Preview: a take's neighbours play as the timeline plays them, from where the take joins them to the other edge of their part in the timeline. A take between two parts of a long split clip used to preview with the rest of the file around it (29 s for a take that is 7.3 s in the cut). With no timeline holding the part, the whole clip plays as before.
- Load settings: a Value Presets node ([comfyui-obvpm](https://github.com/chanon/comfyui-obvpm), 0.2.14 or newer) is listed setting by setting instead of as raw widget text. Each changed value is its own row. A changed schema, and each workflow preset that differs, is one row, unticked by default, with what changed inside it (per field: type, default, `when`, tooltip; per preset: its values) behind a collapsed toggle. Loading the preset label no longer puts that preset's stored values over the take's own.
- Fixed ([#15](https://github.com/chanon/comfyui-magik-timeline/issues/15)): clips could show **no mctx** (and extends fell back to the pixel route, with no loop option) although their `.mctx.safetensors` was right beside them, when the browser could not read the sidecar itself. The server now answers for it, and a clip without a usable sidecar says why in its tooltip: no sidecar, a sidecar that no longer matches the video, or one that could not be read.
- Takes extended or prepended from a clip in another folder now record where that clip was, so Result Preview can show them together instead of the take alone.
- A `base_folder` typed with backslashes (`projects\my_project`) now works like `projects/my_project`. The Timeline's clip menu used to find nothing in it.
- The Timeline's upscale toggle can now be read before a run. With [comfyui-obvpm](https://github.com/chanon/comfyui-obvpm) 0.2.14 or newer, the workflow shows which engine settings the next run will use: Override Bundle Values shows their values, and the Value Presets the run will not use are faded.
- Upscaling: a timeline with hard cuts (unrelated clips, gray seams) or empty space can now be upscaled. It is split into segments that are upscaled, refined and rendered separately (`upscale_00001_s01.mp4`, `_s02`, ...) and joined into one finished `upscale_00001.mp4`, black for empty space, the sound de-clicked at the cuts. Before, such a timeline failed with "not on the latent grid", or its second shot started mid-cycle.
- Upscaling: only what the cut shows is upscaled and refined. A take trimmed to a few seconds is no longer processed whole, and the rendered file now ends where the last clip's cut says (it used to run to the end of the last take).
- Upscaling: a cut made by hand on a seamless (green) seam is now honoured as a cut. Before, the upscale silently played the natural join instead.
- The "not on the latent grid" error now names the clip and the nearest frames that would work.
- Fixed: colours of saved takes and upscales looked shifted in browsers (including the timeline preview), video players and editors -- greens duller, skin and warm tones redder. Videos are now encoded with the BT.709 colour matrix and tagged as such, like ComfyUI's own Save Video. Takes saved before this update keep playing as before, and a timeline mixing old and new takes still previews and exports correctly, only slower: such a preview or export is re-encoded as a whole instead of copied.
